# HPP V6 Growth Law

## Purpose

V6 should not be a panic restart or a copy of V2.

V6 should be the first fresh model that begins with the rules HPP learned the hard way:

- V2 is the wild growth chamber.
- V5 is the clean evidence architecture.
- V6 is the next-generation growth run, built only after the lessons are written down.

This document is the constitution for that next run.

## Prime Rule

Grow first. Reuse depth. Gate maturity.

Plasticity without stabilization becomes noise.
Stabilization without context becomes rigidity.
Depth without maturity becomes loop amplification.

## Inheritance Map

V6 should inherit principles, not unstable artifacts.

### From V2

V2 contributes field lessons:

- speech can improve from concept clusters toward sentence-shaped output
- freezing the deeper developmental stack is safer than constantly retraining the whole system
- speech-facing adapters need their own curriculum
- raw plugged recurrence can make immature speech worse
- stable maturity-gated speech profiles sharply reduce regression and format leakage
- long training jobs should be split into bounded restartable cycles

V2 should not be copied wholesale into V6.

### From V5

V5 contributes the evidence discipline:

- registered evals before broad claims
- JSON aggregate artifacts
- replayable JSONL trajectories
- explicit boundary language
- buyer-safe mechanism framing
- repeatable CUDA and battery-mode constraints
- no claim is promoted without a test path

V5 should remain the clean notebook while V6 grows.

## Minimum Language Gate Before V5 Integration

V2 language does not need to be impressive before V5 learns from it.

It must become reliably measurable.

Before any V2 speech behavior becomes V5-native, it should pass these gates:

- stable profile beats raw plugged mode across a held-out prompt set
- format leakage is near zero
- repetition loops are measured and controlled
- identity/protection phrases do not dominate ordinary dialogue
- deeper recurrent depth only activates when maturity supports it
- output can complete clean sentence-shaped answers
- transcript artifacts are saved for every checkpoint and seed
- weak checkpoints are rejected instead of promoted

Field update, 2026-05-20:

The V2 stable adapter path passed the current V5-safe held-out language gate:

- `225/225` pass
- `0` format leaks
- `0` mode-label leaks
- `0` repeated sentence failures
- mean loop score `0.6933`

This is sufficient to begin V5 integration review for the adapter path. It is not sufficient to promote raw V2 speech or claim mature fluency.

The first V5-native speech target is not brilliance.

The first target is clean, bounded, measurable speech.

## V6 Architecture Laws

### 1. Eval-First Growth

Every growth cycle must produce:

- checkpoint identity
- seed
- device
- power mode
- training duration
- memory notes
- held-out prompts or probes
- aggregate scores
- trajectory or transcript logs
- boundary notes

No silent growth.

### 2. Habit-14 Stabilization

Repeated exposure should not immediately become permanent structure.

V6 should treat `14` successful repetitions as a stabilization threshold, not a magic number.

Before threshold:

- high plasticity
- low protection
- more exploration
- more noise tolerance

At and after threshold:

- protected recall can activate
- maturity score can increase
- pathway confidence can rise
- deeper reuse may become available

### 3. Context-Aware Protection

V6 should protect core patterns without freezing all surrounding context.

A mature pathway should know the difference between:

- the stable core
- the current context
- a distractor
- an out-of-distribution signal

Rigid full-pattern locking is a failure mode.

### 4. Maturity-Gated Depth

Recurrent depth is a routed resource.

Immature pathways get shallow depth and stronger format control.

Mature pathways can earn deeper recurrence after proving:

- low loop score
- low format leakage
- stable held-out behavior
- clean sentence completion
- no phrase collapse

More compute is not automatically more intelligence.

### 5. Stress And Tap-Out Routing

V6 should route differently under calm, stress, and unknown-state conditions.

Calm state:

- nurture path
- richer refinement
- exploration allowed

Stress state:

- sentinel path
- reduced complexity
- safety and stability first

Unknown or extreme state:

- tap-out path
- conservative fallback
- no pretending the system understands

Different profiles may have different redlines.

### 6. Speech Adapter Over Protected Core

The voice is an adapter, not the whole mind.

V6 should not destabilize the core just because speech is rough.

Speech training should focus on:

- clean endings
- ordinary dialogue balance
- anti-repetition decoding
- output normalization
- mode routing
- held-out prompt behavior

Identity can be preserved without being repeated constantly.

### 7. Split-Cycle Training

Long monolithic runs are not the default.

On RTX 4050-class field hardware, V6 should prefer bounded cycles:

1. train briefly
2. checkpoint
3. exit cleanly
4. relaunch
5. evaluate
6. continue only if the checkpoint earned it

This reduces memory accumulation, allocator pressure, and hidden long-run failure.

### 8. Buyer-Safe Boundary Discipline

V6 may be bold internally.

Externally, it must stay precise.

Do not claim:

- finished AGI
- sentience
- human-equivalent cognition
- production-safe autonomy
- fixed `3000x` efficiency
- mature conversation before held-out speech tests prove it

Do claim only what the evals support.

## V6 Birth Criteria

Do not create the real V6 model until these are ready:

- this growth law is accepted as the governing document
- V5 has a stable registered eval suite
- V2 speech has transcript logs and held-out regression results
- the first V6 eval list is defined before training starts
- checkpoint promotion and rejection rules are written
- battery, plugged, and demo modes are respected

## First V6 Eval List

The first V6 eval suite should include:

- Habit-14 protected recall
- changed-context recall
- maturity-gated depth
- stress-aware routing
- tap-out boundary profiles
- named-baseline attractor recovery
- speech format leakage
- speech repetition score
- held-out ordinary dialogue prompts
- transcript quality review

Speech evals should be added before speech claims are promoted.

## First V6 Training Shape

The first run should be small and boring:

- small core
- explicit seed
- short split cycles
- no giant dataset first
- no uncontrolled recurrence
- no full-stack speech training
- transcript logging from the beginning
- checkpoint promotion only after held-out tests

The goal is not to make V6 huge.

The goal is to make V6 honest, measurable, and developmentally stable from birth.

## Position

V6 should be the first HPP model that starts life with a childhood plan.

V2 proved there is something alive in the growth direction.
V5 proved the evidence can be organized.
V6 should prove the next run can grow under law.
